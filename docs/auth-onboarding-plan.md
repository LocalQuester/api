# 인증과 온보딩 연동

## 확정된 정책

- 카카오와 구글만 지원하며 로컬 로그인은 제공하지 않습니다.
- 사용자는 `(provider, providerUserId)`로 식별합니다. 이메일이 같아도 다른 제공자는 별도 계정입니다.
- 계정 자동 병합과 계정 연결 기능은 제공하지 않습니다.
- 소셜 인증 성공과 회원가입 완료를 구분합니다. 필수 약관 동의와 닉네임 검증을 통과하고 프로필 사진 선택 또는 건너뛰기를 완료해야 가입 완료로 처리합니다.
- 온보딩의 마지막 진행 단계를 서버에 저장하는 이어하기 기능은 제공하지 않습니다.
- 온보딩 미완료 계정은 재로그인 시 약관 화면부터 시작합니다. 진행 중 화면 간 이동을 위한 프런트 상태와 재로그인 후 서버 단계 복원은 별개입니다.
- 미완료 계정의 인증만으로 가입 완료 회원용 API를 사용할 수 없도록 서버에서 구분합니다.
- 닉네임은 한글 음절과 자모, 영문 소문자, 숫자로 2~10글자를 허용합니다. 대문자는 자동 변환하지 않고 거부합니다.
- 금칙어는 서버 관리 목록으로 시작합니다. 씨발, 병신, fuck이 포함된 닉네임은 거부합니다.
- 예약어 관리자, 운영자, admin, administrator, localquester는 정확히 일치하면 거부합니다. 10글자를 넘는 예약어도 목록에 유지합니다.

## 현재 코드와 필요한 변경

| 구분 | 현재 구현 | 다음 작업 |
| --- | --- | --- |
| 소셜 인증 | Google 및 Kakao 시작과 callback, 일회용 티켓, 세션 교환 | 실제 제공자 설정 후 로컬 연동 검증 |
| 사용자 식별 | 제공자와 제공자 사용자 ID로 조회 | 신규 가입 동시 요청 처리 검토 |
| 세션 | DB에 토큰 해시 저장, 내 정보 조회, 로그아웃 | 기간 정책 협의 후 현재 고정값 검토 |
| 가입 상태 | 별도 완료 필드 없음 | 완료 시각 등 최소한의 완료 상태 추가, 미완료/완료 응답 설계 |
| 프런트 callback | 항상 `/home`으로 이동 | 서버 가입 상태에 따라 약관 화면 또는 홈으로 분기 |
| 약관 | 프런트 더미 문구와 체크 상태 | 버전과 동의 기록 방식 협의 |
| 닉네임 | 프런트 형식 검증과 중복 예시 | 확정된 정책에 따라 서버 검증 및 DB 유일성 보장 (이슈 #6) |
| 프로필 사진 | 브라우저에서 자르기 및 임시 File 저장 | 저장 방식과 업로드 및 정리 정책 협의 |
| 가입 완료 | 프런트 화면 이동만 구현 | 최종 검증과 가입 완료 저장 API 설계 |

소셜 제공자의 표시 이름과 사진이 현재 `users`에 들어가더라도 이를 사용자가 선택한 닉네임이나 온보딩 완료로 간주하지 않습니다. 실제 필드 분리 여부는 가입 API와 DB 변경을 설계할 때 결정합니다.

## 구현 전 협의가 필요한 정책

- 금칙어 및 예약어의 추가나 차단 방식 변경은 사용자 협의 후 반영
- 약관의 버전 식별, 동의 저장 시점, 선택 동의 기록 방식
- 로그인 유지 기간과 세션 만료 후 처리
- 프로필 사진의 서버 허용 형식, 저장소 접근 방식, 임시 업로드 정리 시점
- 미완료 계정 및 데이터의 보관과 정리 기준

이미 적용된 마이그레이션은 수정하지 않고 새 파일을 추가합니다.
